# 本機瀏覽器完整遊玩路線圖

## 完成標的與邊界

本機執行 `python -m eragvt`，玩家能在瀏覽器操作原作已完成、可到達的功能：完整開局、所有模式與設定、角色編輯、日常與戰鬥事件、結局／引繼、成就及存讀檔。不是「預設設定跑滿200回合」就完成。
原作明確停用／未完成的內容保持原狀，不續寫作者沒有完成的情節或規則；每一豁免必須有具體原文與範圍。原作錯誤與移植缺口分開處理，不能把兩者都稱為未完成。
技術邊界沿用既定規格：原生Python遊戲邏輯、原文catalog、單人本機Web、版本化JSON；舊Emuera `.sav` 匯入與AI敘事不在本次完成標的。原作一般玩法及已實作的除錯入口仍須盤點，不以「罕見」略過。

## 文件分工

- [STATUS](STATUS.md)：現在完成到哪、正在做哪一包、最新驗收。
- [PLAYABILITY](PLAYABILITY.md)：系統現況、完整停止點歸屬、無操作／原作未完成證據；不在此另排順序。
- 本頁：**唯一後續工作佇列**、依賴與完成條件。未決細節仍在 [unresolved](wiki/bridge/unresolved.md)／[deviations](wiki/bridge/deviations.md)。
- `S01…S56` 是歷次工作紀錄，不是總進度或完成比例。S01–S07完成垂直切片，S08–S55擴充；原始規劃只將S08以後列為橫向擴充，歷史由git保留。

## 每次「繼續」的固定流程

1. 讀AGENTS → STATUS → 本頁；取目前工作包尚未完成的第一個完整成果，先寫≤60行session規格，引用工作包ID與驗收矩陣ID。
2. 查原作入口、全部分支及引擎語意，先列expected與table-driven測試，再手寫實作；新模組當次接入真實呼叫者。
3. 通過定向測試與Web邊界測試，對該包受影響的畫面做**真瀏覽器**操作；後端API通過不能取代此項。
4. 全pytest；有遊戲流程變動跑標準500局（兩開局各seed0–249、max-shop200、actions101–108、前景50局一批），逐seed和上一階段比較停止／catalog失敗，說明預期差異。
   S60起依使用者2026-10-06裁決使用全新25歲人工資料，建立獨立500局基線；保留上述參數，與S59只並列停止表及記錄差異，不宣稱原資料逐seed等價。後續沿用同一人工基線逐seed比較；產品年齡規則不變。
5. 更新同一工作包現況、驗收證據及必要wiki；清理已過時的停止說明。確認唯讀目錄、LF／UTF-8、明確stage、commit/push main。
6. 回報成果／依據／裁決；若只完成包內一個成果，下次仍留在同包。包的全部完成條件達成才換下一ID。
