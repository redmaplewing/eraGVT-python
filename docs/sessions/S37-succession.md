# S37：通關後引き継ぎ

## 目標與範圍
- 使用者同意繼續上一階段建議：手翻 SUCCESSION.ERB，完成本階段後停止。
- 接通既有通關結局入口、繼承選單與確認、資料保留／重置、繼承後遊戲續行。
- 依原作實作必要的設定及初始化依賴，不新增選項或任意簡化保留資料。
- 天使の樹戰鬥是後續獨立階段，仍遇未移植功能即明確停止，不繞過。

## 實作要求
- 先讀 AGENTS.md、STATUS、PLAN，再按需要查對應 wiki、原作及引擎。
- 先由 ERB 推導 table-driven 測試，確認紅燈後手工翻寫原生 Python。
- 原作引用檔案@函式:行號；引擎的重置、角色刪除／索引、存讀檔等語意必須查證並附行號。
- 選單輸入依原作等待，預設路徑照原作；RNG 注入並保持呼叫順序。
- 查驗 RESULT／RESULTS、GLOBAL、暫存及角色資料在繼承前後的實際語意。
- 新模組接上遊戲流程，補代表性的結局→繼承→續行整合測試。
- source/、reference/ 永遠唯讀；不變更既有裁決。
- 新未知／偏離須回報，不能自行決定替代行為。
- 文件繁體中文，LF、UTF-8 無 BOM。

## 驗收與收尾
- 程式與測試先固定，再跑最終全套 pytest 與模擬。
- 標準預設／tokusou 各 seed 0–249、max-shop 200、actions 101–108。
- 各 50 局前景批次，保留逐局 log、JSONL 與退出碼，核對 seed 全集。
- S36 基準：預設 246 上限／4 回標題；tokusou 250 上限；catalog 失敗 0。
- 另外驗證實際通關入口觸發繼承及續行；若用人工狀態需清楚標示，不能冒充自然通關模擬。
- 更新 STATUS（≤120 行）與相關 wiki；有新增事項才更新 unresolved／deviations。
- 確認唯讀目錄未動、git diff --check 與檔案編碼通過。
- 子 agent 不 commit／push；主 agent 獨立驗收後 commit 並推上 main。
- 回報：做了什麼／已查證的依據／需要使用者決定。
